Session Summary — July 15, 2026
=================================
Estimated hours: 3

- Studied how the React frontend connects to the Django backend
  - React calls fetch("/api/...") which Vite proxies to Django on port 8002
  - Django REST Framework ViewSets handle the request and return JSON
  - The flow: React component → Vite proxy → Django router → ViewSet → Serializer → Model

- Learned about TypeScript interfaces
  - Define a type that mirrors the fields the Django serializer returns
  - Gives autocomplete and catches typos at compile time

- Learned about React hooks for fetching data
  - useState stores data and triggers re-renders when updated
  - useEffect runs side effects (like fetch calls) when the component mounts
  - Empty dependency array [] means "run once on mount"

- Decided on a project structure for the frontend
  - src/types.ts for shared TypeScript interfaces
  - src/pages/ReportIndex.tsx for the report list page
  - src/pages/ReportView.tsx for a single report detail page
  - App.tsx handles routing between pages

- Learned about react-router-dom for page routing
  - /reports shows ReportIndex, /reports/3 shows ReportView
  - :id is a URL parameter the component can read

- Understood the two-router system
  - Django's router (backend/urls.py) handles data — which Python code runs for an API request
  - React's router (App.tsx) handles what you see — which component renders for a URL
  - They work together: React router shows the page, page fetches from Django router

- Learned how to POST data from React
  - Use FormData for file uploads (matches Django's MultiPartParser)
  - Don't set Content-Type manually — FormData handles it

- Created DEVLOG_FRONTEND.md to document all of the above
